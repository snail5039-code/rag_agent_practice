에이전트 평가 도구를 만들고, 청킹·모델·검색·프롬프트를 바꿔 가며 평가해서
**정답률 0.81 → 0.90**으로 올렸다 (200문제 기준).

## 오늘 한 것

### 1. 골든셋 합치기
- 제공 골든셋 267개 + 내 골든셋 77개 → `data/goldenset_all.csv` **309문제** (겹치는 35개는 한 번만)
- 빠르게 비교하려고 분야·근거 유형 비율을 맞춰 뽑은 `data/goldenset_200.csv` **200문제**도 만듦

### 2. 에이전트 평가 도구 만들기 (`pipeline/evaluate_agent.py`)
- 골든셋 문제를 에이전트에 하나씩 풀리고 채점
- 채점 항목: 답 정확도(LLM 채점, openevals), 근거 쪽 적중, 보류 판단, 검색 횟수, 응답 시간
- 중간에 끊겨도 다시 실행하면 이어서 풂

### 3. 코드 정리
- 여러 파일에 같은 코드가 반복되던 것을 공통 함수로 모음 (183줄 줄어듦)
- 정리 전후 추출·청크·검색 결과가 똑같은지 확인함
- BM25 색인을 파일로 저장해 두고 재사용 → 시작 시간 20초 → 0.2초

### 4. 모델 고르기
| 모델 | 질문당 시간 | 결과 |
|---|---|---|
| gemini-3.6-flash | 11초 | 잘함, 느림 |
| **gemini-3.5-flash-lite** | **4초** | **재검색·보류 잘함 → 선택** |
| gemini-2.5-flash / lite | 5초 | 재검색을 안 함, 보류 표시가 틀리기도 함 |

- 채점 모델도 3.5-flash-lite로 고정 (4개 모델 모두 채점은 정확했고 가장 빠름)

### 5. 청킹 비교 (300/50 · 500/60 · 800/100)
| 청킹 | 검색 점수 (MRR) | 에이전트 정답률 (2회) |
|---|---|---|
| 300/50 | **0.830** | 0.786 / 0.796 |
| **500/60** | 0.819 | **0.827 / 0.811** |
| 800/100 | 0.812 | 0.806 |

- 검색 점수는 300/50이 좋았지만, 실제 답 정확도는 500/60이 두 번 다 높아서 **500/60 선택**
- 배운 점: 검색 점수만 보고 청킹을 고르면 안 된다

### 6. 왜 틀리는지 분석 (RAGAS + agentevals)
- **RAGAS**: 틀린 34문제 중 24개는 **검색 문제**
  - 맞는 쪽은 찾았는데, 그 쪽에서 답이 적힌 조각은 못 가져옴
  - 그래서 "근거가 없다"며 보류 → 에이전트 판단은 오히려 맞았음
  - 답을 지어내는 문제는 거의 없었음
- **agentevals** (검색 과정 채점)
  - 분야(domain)를 잘못 고르면 정답률 0.3 수준
  - 표 질문에 쓰던 MMR 검색이 오히려 불리했음 (표의 한 줄만 가져옴)

### 7. 검색 고치기
| 바꾼 것 | 정답률 |
|---|---|
| 처음 | 0.827 / 0.811 |
| ① 찾은 조각의 앞뒤 조각도 같이 넘기기 | 0.806 |
| ① + ② 표 질문도 일반 검색(Hybrid) | 0.842 |
| **① + ② + ③ 분야를 골라도 전체 결과 섞기** | **0.872 / 0.898** |

### 8. 프롬프트 고치기 (p1 → p2)
- 표 숫자로 계산할 수 있으면 계산해서 답하기 ("비교 문장이 없다"며 보류하지 않기)
- 질문이 여러 부분이면 빠짐없이 답하기
- 질문과 연도·대상·단위가 같은 숫자 쓰기
- 결과: 정답률 **0.888 / 0.903**, 표 질문 0.67~0.76 → **0.818**
- 답이 없는 문제는 여전히 100% 보류 (억지로 답하지 않음)

## 알게 된 것
- RAG는 추출 → 검색 → 답변 단계마다 조금씩 놓쳐서 100%는 거의 안 나온다
- 같은 설정도 돌릴 때마다 1~2%p 흔들린다 → 중요한 비교는 두 번 돌려서 확인
- 틀린 답보다 보류가 많다 = 모르면 지어내지 않는다 (좋은 방향)
